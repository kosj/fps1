# 기술 결정 기록

결정이 바뀌면 항목을 지우지 않고 아래에 새 항목을 추가합니다.

## 2026-11-26

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 엔진 | Godot 4.7, GDScript | Windows 화면 품질(Forward+), 텍스트 기반 씬, 라이선스 비용 없음. C#은 웹 내보내기가 안 됨 |
| 플랫폼 | Windows, 웹 | Windows가 기준 품질, 웹은 같은 게임의 가벼운 화면 프리셋 |
| 웹 렌더러 | Compatibility (WebGL 2) | Godot 4.7 웹 내보내기는 WebGL 2만 지원 |
| 게임 형태 | 6v6 멀티플레이 PvP (팀 데스매치, 점령전) | 콜 오브 듀티 멀티플레이를 레퍼런스로 함 |
| 1차 범위 | 맵 3개, 무기 8~10종, 봇 포함 | 좁은 범위를 높은 품질로 마감 |
| 세계관 | 근미래 밀리터리 (잠정) | 가상의 총기 디자인으로 실제 상표를 피하기 쉬움 |
| 네트워크 구조 | 전용 서버 권위, 클라이언트 예측, 지연 보상 | 웹 클라이언트는 코드가 노출되므로 서버 판정이 필수 |
| 물리 | Jolt Physics, 60Hz | 서버와 클라이언트가 같은 설정 사용 |
| 입력 액션 | 코드로 등록 (`game/core/input_setup.gd`) | project.godot의 직렬화 이벤트보다 변경 이력이 읽기 쉬움 |
| 스크립트 참조 | `preload` 상수 | 헤드리스 테스트가 전역 클래스 캐시에 의존하지 않게 함 |
| 3D 에셋 | Varco 3D 생성 → Blender 폴리싱 → GLB | Varco는 PRIVATE 라이선스로 생성 |
| 사운드 | ElevenLabs (효과음, 음성, 음악) | 유료 플랜에서 상업적 이용 |

## 2026-11-26 (M2)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 전송 방식 | 전 플랫폼 WebSocket | 웹과 Windows가 같은 서버에 붙을 수 있는 가장 단순한 방식. TCP라 패킷 손실 시 지연이 커질 수 있어, 실제 인터넷 환경 테스트 뒤 WebRTC 데이터 채널로 바꿀지 다시 판단 |
| 넷코드 | 직접 구현 (`game/net/game_session.gd`) | 커뮤니티 애드온 netfox를 검토했으나, 탄 판정과 지연 보상을 직접 제어하고 외부 의존성을 줄이기 위해 자체 구현 |
| 틱과 스냅샷 | 시뮬레이션 60Hz, 스냅샷 30Hz, 보간 지연 100ms | FPS에서 일반적인 값. 실측 뒤 조정 |
| 서버 시뮬레이션 | 도착한 입력만큼만 진행, 밀리면 한 틱에 2개까지 | 서버 상태가 항상 "N번 입력까지 적용한 결과"가 되어 클라이언트 예측과 정확히 비교 가능. 속도 조작 여지도 제한 |
| 지연 보상 | 물리 엔진 대신 수식으로 판정 (`game/combat/hit_math.gd`), 되감기 상한 300ms | 과거 위치로 물리 객체를 옮기지 않아도 되고 결과가 결정적이라 테스트 가능. 히트박스는 축 정렬 상자로 근사 |
| 입력 검증 | 형식, 순서, 범위, 양을 서버에서 검사 | 웹 클라이언트는 코드가 노출되므로 클라이언트를 신뢰하지 않음 |
| 충돌 레이어 | 1 월드, 2 캐릭터 몸체, 4 히트박스 | 플레이어끼리는 통과, 탄은 히트박스로만 판정 |

알려진 한계:

- 예측이 틀려 보정될 때 화면이 순간 이동한다(사망과 리스폰 시점에 발생). 오차를 몇 프레임에 걸쳐 풀어 주는 보간이 필요하다.
- 히트박스가 몸의 회전과 자세를 반영하지 않는 상자 2개다. 캐릭터 모델이 들어오면 부위별로 나눈다.
- 실제 인터넷, 패킷 손실, 다수 인원(12명) 환경에서는 아직 검증하지 못했다.

## 2026-11-26 (M4 일부)

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 기본 실행 방식 | 서버 없이 봇과 대전 | 웹 주소만으로 바로 게임이 되고, 서버 비용 없이 플레이테스트 가능 |
| 봇 구조 | 봇이 사람과 같은 입력(InputCmd)을 만든다 | 이동, 무기, 판정 규칙을 봇용으로 따로 만들지 않아도 되고, 서버에서도 그대로 동작 |
| 봇 길찾기 | 내비게이션 메시 없이 순찰 지점 사이를 직진, 막히면 뛰어넘거나 다른 지점 선택 | 그레이박스 단계에서는 충분. 실제 맵이 생기면 내비게이션 메시로 교체 |
| 경기 규칙 | 팀 데스매치, 30킬 또는 5분, 아군 사격 없음 | 1차 범위의 첫 모드 |

봇 난이도(반응 0.5초, 조준 오차)는 자동 테스트로 정할 수 없는 값이라 잠정치다. 봇끼리 60초 대전에서 명중률은 약 30%였다.
